Conclusion: the op0=0xf 2-slot FLIX FORMAT is decoded+executed by the core in the user-kernel
context (7/9 op0=f bundles ran, PC continued). This overturns "FLIX unreachable": that was a
TOOLCHAIN limit (esp-elf can't assemble TIE), not a hardware one -- verbatim byte-splice runs.
Ceiling that REMAINS: (1) op0=0xe format faults illegal (201) in this context; (2) specific
op0=f op encodings are still illegal (fb8); (3) RUNNING != COMPUTING -- to get verified vector
math we still need the TIE op semantics + vector load/store encodings with correct register
setup. Next: empirical semantics -- sweep op0=f bundles that DO drive memory via a controlled
address in a3, dump full buffer, correlate input->output to decode the vector load/MAC/store ops.
